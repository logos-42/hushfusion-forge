# 持续学习闭环 —— 诚实的负面结果（真 forge 评估）

## 验证结论（必须直面）

服务器 12 轮真 forge 评估：

```
headless top-K score 中位数均值: 0.186
随机 top-K score 中位数均值:    0.324
平均 lift:                       -0.137   （headless 被随机打败）
连续改善(后3轮-前3轮):            -0.070   （没有越学越好）
```

**headless GVF 作为设计选样器，在真 forge 评估下被随机基线打败，且不随轮次改善。**

## 我犯了什么错（三层）

**1. oracle 近似是假阳性**
- orace 模式 lift +0.158，真评估 lift -0.137 —— 完全相反。
- 根因：oracle 用"最近邻已知设计的 score"当候选分，隐含"接近已知高分=高分"的偏置，
  这本身就在替 headless 作弊。真评估（forge 真正搜索 headless 选的起点）才暴露真相。

**2. "学习量是主杠杆"被证伪**
- 只学 top-K(5个/轮) → -0.148；全量回流(58/轮) → +0.015 后又不稳定；服务器 12 轮 → -0.137。
- 数据量不是瓶颈。加大学习量不改善，甚至更差。

**3. GVF 线性表达力不足（根因）**
- headless 的 GVF 是**线性** TD(λ)：value = w·φ。12 维电磁设计空间里"高 score 设计"结构复杂
  （电流+半径+z 的组合效应），线性函数抓不到。
- 我用**多变量逻辑回归**（非线性 + 标准化全量训练）时 CV 0.977、跨 spec 迁移 0.68——
  但那是一次性训练，不是在线持续学习，且没用 headless 引擎。

## 对比：两条路

| 方法 | 训练方式 | 我的实测 |
|---|---|---|
| headless GVF（线性在线） | 在线 TD，持续学 | 真评估 lift **-0.137**（被随机打败）|
| 多变量判别器（逻辑回归） | 一次性全量 | CV **0.977**，跨 spec 迁移 0.68-0.70 |

## 建议的下一步（不是继续堆迭代）

headless 的 GVF 线性价值函数对这个任务表达力不足。真正的接合点应该在**两个方向之一**：

**A. 换更强的 headless 组件**：headless 不止 GVF —— 它有 PLN 头（非线性）、OML 元学习、
CausalProposer。用带非线性头的 headless 组件（而非最简 GVF）做设计价值函数。

**B. 承认"选样器"不是 headless 当前擅长点，改用已验证的多变量判别器**：
把 CV 0.977 的判别器做成选样核心（它已证能区分高低分 + 跨 spec 迁移），
headless 的持续学习优势留给真正适合的序列任务。

**我的判断**：先走 B —— 用已验证的多变量判别器（不依赖 headless）把"headless 设计闭环"换成
"多变量规则驱动搜索"，因为那条路已有 0.977 的量化支撑；headless 的持续学习价值留到它能发挥的
序列/流式场景，不强塞进设计选择这一步。
