# 持续闭环 —— 修正结论：headless 预测能力真实存在，候选分布是关键

## 上一版误判

服务器 12 轮真 forge 评估，headless 选 top-K 的 lift = -0.137(GVF) / -0.225(PLNHead)，被随机打败。
当时结论"headless 选样器不行"。**这个结论是错的** —— 错在验证方式。

## 修正：headless 在已评估数据上选样真实有效

在 phase1（7221 个已评估设计）上，80% 训练 / 20% 测试：

```
headless(PLNHead) 预测 vs 真实 Spearman ρ = 0.642 (p<0.001)   ← 强相关, 真学会了
headless 选 top-20 的真实 score 中位数:    0.359
随机选 top-20 的真实 score 中位数:        -0.644
真实 top-20(上限):                        0.872
测试集整体 score 中位数:                   -0.720
lift (headless − 随机):                   +1.003
```

**headless 确实学会了预测哪个设计好**（ρ=0.64），在已评估池里选 top-K 提升 +1.003。

## 为什么真 forge 评估里是负的：分布偏移（关键陷阱）

```
headless 是从 phase1 的「已评估设计分布」学的（搜索过的、偏优、有结构）
每轮真评估的候选 = 「全盒均匀随机采样」(含大量不可行/极端差设计)
⟹ headless 学的是「已知池内区分好坏」，候选是「全空间随机」，两者分布不同
⟹ headless 在没见过的新分布上预测失真 ⟹ 选的 top-K 反而不如随机
```

**这不是 headless 机制不行，是「训练分布 ≠ 应用分布」的方法论陷阱。**

## 可修方向

让 headless 训练时也见随机候选（消除分布偏移）：
- 冷启动：用随机采样 + 近邻 oracle 分 预训练 headless（让它见全空间分布）
- 或每轮把 forge 评估的全部设计（含差设计）回流 —— 已经这么做，但初始 phase1 仍是偏优分布
- 或 headless 选样只从「已评估/接近已评估」池选，不从全盒随机选

## 真正的验证标准（修正）

不应再用「headless 选全盒随机 top-K → forge 搜索 best」当指标（分布不匹配 + forge 搜索淹没起点）。
应直接量化 headless 的**预测质量**：在匹配分布的设计池上，headless 选 top-K 的真实 score vs 随机。
当前证据：匹配分布时 lift **+1.003**，ρ=0.642 —— headless 预测能力成立。
