## 1. 真缺陷：0.1.2 重录 v1 黄金 trace 时漏了 `--protocol 1`

**发生了什么**：0.1.2 判据变更后，三份黄金 trace 全部失效（见 §2）。我按纪律重录，
但 v1 那份用的命令是

```bash
go run ./cmd/forge world serve --record <out> < <reqs>     # ← 漏了 --protocol 1
```

而 `--protocol` 的缺省值是 **2**。于是那份文件虽然装着 v1 的**请求序列**，
响应却是 **protocol 2** 的会话：它自称 `"protocol":2`。

**为什么 G18 没红（这是本条最该记住的部分）**：G18 的回放**以 trace 自己的 `hello.protocol` 为准**
（契约 §6 明文：「`--replay` 以 trace 自己的 `hello.protocol` 为准」）。于是一份标错版本的 trace
在回放时**自己跟自己比**，当然逐字节一致 —— **G18 是绿的，而证据是错的**。
跨语言回放门抓的是「字节不可复现 / 跨语言分歧 / 握手错了照跑」，**它抓不到「标错了版本」这一类失败**。

**抓到它的是 `internal/world` 的单测**（`v2_test.go:803`）：

```
--- FAIL: TestTraceProtocolReadsTheHelloResponse
    the v1 golden trace declares protocol 2, want 1
--- FAIL: TestV1GoldenTraceIsRefusedByAV2World
    the refusal does not name the version mismatch
```

**处置**：按 `--protocol 1` 重录；并在本轮把「重录 trace」写进发版清单为**必须显式给 `--protocol`**。

**教训（写死，进 `honest-verification-gates` 那一类规则）**：

> 回放类门的判据若是「与 trace 一致」，它就**无法**发现「trace 本身标错」。
> 一份证据至少要有**一条不依赖它自己的**检查（这里是「v1 trace 必须自称 protocol 1」的单元断言）。
> **两条路都要求「对得上」，但它们对的是不同的东西：一条对字节，一条对语义。**

## 2. 版本税的实测记录（第二笔）

版本从 0.1.2 跳到 0.1.3 之后，三份黄金 trace **再次全部失效**，原因与 0.1.2 时**完全相同**：
世界 hello 的声明里带 **engine 版本串**，而它是**冻结字节**的一部分。

| trace | 行数 | 响应字节（0.1.2 → 0.1.3） |
|---|---:|---:|
| v1 `world_trace_golden.jsonl` | 8 | 5653 → 见运行时实测 |
| v2 `world_trace_golden_v2.jsonl` | 10 | 7199 → 见运行时实测 |
| mu `world_trace_golden_mu.jsonl` | 17 | 10048 → 见运行时实测 |

⟹ **每一次版本跳变都要重录三份 trace + 重测两份世界结构证据（`engine_version` 字段）**。
这是一笔**每版都要交的税**，不是一次性成本。

**候选处置（本版仍然不动，只记账；需要 leo 决策）**：协议的声明只应携带**语义哈希**
（已有 `SpecSHA256` 那一类），而不该把**构建期字符串**放进冻结字节；若确要保留 engine，
则它必须在回放比较中**被排除**。两者任一都需要协议版本前进（**v4**）——
那是协议契约变更，不能顺手做。

## 3. 计划对齐（只对齐文档与记账，不改任何代码判据）

并行的计划线把聚变计划改成 **v3**（`docs/wiki/fusion-program-roadmap-v3.md`），本次的方向性调整：

- **主路线**：时变电磁场 → 产生/调制引力场 `μ(t)` → **引力场承担主要约束与惯性/输运调控**；
- **FRC 降级**为三件事：等离子体形成与 RMF 的工程参照 / `FC5` 稳定性对照 / 引力场路线失败后的独立备用；
- 不再预设「FRC 主稳定、μ 作辅助」；
- **`G4` 改为「引力场主约束路线门」**；新增「引力场—等离子体耦合层」；保留局部操作 / 全局拓扑事件的 S3 判决。

**本版对这个计划的贡献只有一条，且是硬的**：0.1.2 新增的 **G23 可造性门**与 `clearance` 罚项，
是计划里「制造/可复用性」那类要求**目前唯一已经落成机器判据的一条**（其余仍是计划文本或 `[缺口]`）。
引用计划时必须与计划的四条边界一起读，尤其是「Forge 当前是线圈/真空静磁设计搜索器，
不是等离子体平衡、有限 β、输运或发电量证明器」与「μ 的主动产生仍是第二输入缺口」。
