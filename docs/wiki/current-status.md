## 一句话状态

Phase 0 的验收问题——**"机器能不能找到一个比人工基线更好的电磁设计，而且这条结论能被独立复现"**——

## 诚实边界（必须与上面的数字一起读）

1. **最优解很可能是不可造的位形。** D9857 把一圈 `a=0.10 m`、`1.78 MA` 的线圈放在距中场采样点
   **4.196 mm** 处——落在求解器 5 mm 的 `alpha2` 钳位半径内。目标函数目前**没有"导体到约束区域的净空"约束**，
   所以它合法地把导体贴到打分点旁边换场强。任何引用 `1.381419` 的场合都必须带这句限定。
2. **热启动的增益在 1000 次预算下不显著**（1.3073 vs 1.3033，后者方差还更小）。
   "继承设计知识值多少钱"在 Phase 0 的答案是：**这个预算下 ≈ 0**。
3. **人工基线在这个盒子里是弱基线**：随机搜索平均 8 次评估就追平它。它赢在"是个真装置"，不赢在指标。
4. 真空静磁模型：没有等离子体、没有平衡、没有有限 β、没有涡流。它回答"这个线圈配置的场结构好不好"，
   **不回答**"这台装置能不能聚变"。
5. `sign_agreement` 恒为 1.000 是**复制证据不是质量分**——规则是由"每个 run 同号"硬过滤出来的，
   该字段存在的意义只是核对过滤没被绕过。

## 内部设计判决层（2026-09-26，接上游 ProjectionPhysics）

Forge v0.1 的评分只问「中平面的场均不均匀」。那让一个把线圈贴到距打分点 **4.196 mm** 的退化解
拿了第一名。本层把上游 `logos-42/Hibs-Physics`（本地工作副本读出时 commit `d28cd417b3f4`）的
内部设计实现成**可计算、可回归**的门，公式与口径逐字移植，不重新发明物理：

| 上游条目 | 本层实现 | 参考装置（a=0.2 m、n=1e20 m⁻³、β=1、15 keV）实测 |
|:--|:--|:--|
| PF3 / FC1 | `BMin`/`NMax`/`NOp` | `B_min = 1.099096321 T`；`n_max(1.6 T) = 2.119182979e20 m⁻³`；`n_op(0.12 T) = 1.192040426e18 m⁻³` |
| FC11b 死活判据 | `BDeath`/`ChiMu` | `B_death(0.2) = 0.996568643 T`，∝1/a（0.10→1.9931 / 0.05→3.9863） |
| FC4 | `XReq`（τ_E = τ₀/√(1−μ)） | `χ_μ(1.6 T, 0.2 m) = 1.479497189`；`x_req = 3.2464897329762205e-04` |
| TD19–TD21 | `WindowCloseStep`/`LockingFactor` | η=0.05、D-T：解析 **164.2411 步**，**第 165 步**窗口关闭（`ceil` 语义，两值分列、不互相冒充） |

六道门（`go run ./cmd/forge design --a 0.2 --source <key>`）+ FC5 单列 `unknown`（上游未证，**不计入 pass**）：
`field_min` / `death` / `mu_window` / `coil_load` / `buildable` / `steps`。

**本轮最值得读的一条判决**（仓库参考装置尺度 a=0.2 m）：

- 场源 `MATBG (N=2) 面外 B_c2 = 0.12 T` ⟹ **无解**：χ_μ = 2.102e-4，μ 窗口关闭（不是「更难」）；
- 场源 `MATBG (N=2) 面内 B_c = 1.6 T` ⟹ 窗口**开**（χ_μ = 1.479），但线圈自身峰场 `B_coil_max = 3.416 T > 1.6 T`
  ⟹ `coil_load` 不过。即：用该材料**做线圈**在这份设计上不成立——这与上游自己的诚实边界
  （「FET 栅控是 MATBG 超导的必要条件，线圈化需逐层栅极——未计工程代价」）方向一致，**不是本仓的新发现**。

**诚实边界**：本层**不算 μ**（μ 的主动产生 = 上游的第二输入缺口，未变），只算「给定 μ 能维持多少步、
需要多大的场」；Forge 的场模型仍是真空静磁学，本层是把静磁学输出**喂进**上游的门，不是把 plasma 加进来；
`fc5_locked` 一律 `unknown`；锚点出处见 `testdata/projectionphysics_anchors.json` 的 `provenance`
（上游 `artifacts/` 被 .gitignore 忽略、不入 git，锚点来自本地重跑 `scripts/verify_moire_field.py` 的产物）。

## 世界协议（2026-09-27，P0，与 headless 的边界）

契约：`docs/world-protocol.md`（**冻结文本**，改动即协议版本变更）。它冻结的是**线协议**，不是新物理：

- **JSONL / stdio**，一行一请求一行一响应；stdout 只放协议行（噪声会让客户端读到错位的响应 = 静默损坏）。
- **最短往返浮点**（`FormatFloat(v,'g',-1,64)` / Python `repr`）：禁 `%.6g` 之类；逐位复现的对象是**响应字节**，不是「数值接近」。
- 消息 `hello / reset / step / close` + 7 个冻结错误码；`info` 字段与 `rlenv.Info` 的 JSON tag 逐字相同。
- **语义唯一权威是 `internal/rlenv`**：协议只搬运与校验，不在这里加 shaping、惩罚或归一化。
- **门 G18（三条一起判）**：Go 逐字节回放 / Python 客户端逐字节回放（跨语言证据）/ 把改坏的 hello 喂给客户端必须非零退出。证据 `testdata/world_trace_golden.jsonl`（8 行 / 响应 3635 字节，由 recorder 生成；抽请求重录 **`cmp` 逐字节相同**）。

**诚实边界（契约 §7）**：本版暴露的是 `rlenv` —— 一个**无时序结构**的设计评分环境（`A ≡ 0`）。headless 的 Options 正是因为在它自己的 `lm4` 上没有时序结构才得到过一个混杂的负结果。**P1 必须先证明 `A > 0` 才允许接 Options**；协议也不吃掉 P1 的工作（「把门变成时序结构」是 `World` 层的语义改动，需要新消息就是 protocol v2）。
